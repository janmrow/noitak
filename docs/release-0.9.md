# Noitak 0.9.0 engineering assessment

Noitak 0.9 adds an ordered collector entry. The webhook pilot uses it to
transform up to 32 deliveries with up to 128 labels each into typed CI jobs.
Archived deliveries and pushes with an explicitly missing ref are skipped.
A main push, archived delivery, missing-ref push, urgent release push and
repeated main push return main, urgent release and main in that order.
The host authenticates deliveries and submits jobs.

The selector preserves repository identity and emits only for active
repositories with a nonempty branch. It forwards the dispatcher's typed job
and the dispatcher's proof covers the urgency bit. The boundary validates
the entire batch and snapshots flags before any row executes, so a malformed
tail fails at the boundary. A reached selector fault fails the entire call.

## Proof and change control

The selector proof covers one typed row under every assignment to its
declared flags. Literal admission, compatible nominal element types,
transitive reads and sufficient output capacity are checked statically.
Induction starts with an empty accumulator. A skipped row leaves the
accumulator unchanged. An emitting row appends one value satisfying the
selector guarantee. After *k* visits the accumulator is exactly the ordered
emissions of those *k* rows and its length is at most *k*. Each derived check
records the selector proof and its static premises.

The traversal and induction rule are trusted compiler semantics. The
row proof depends on checked IR, Z3 translation and the pinned solver.
Finite enumeration can veto a definitive result on a small row domain.
Artifact validation exercises the deployed JavaScript and independently
checks whole-array expectations on supplied vectors. It does not establish
universal compiler equivalence. Application authorization and arbitrary
whole-output contracts are outside the proof.

## Observed changes

The gate compares selector contributions under fixed grants and checks
refinement of the selector guarantee over hypothetical results. A
distinguishing contribution is replayed as a one-row host call on both
revisions. The proof of equivalent contributions and the common traversal
rule extend comparison to admitted batches.

| Candidate | Finding | Gate |
| --- | --- | --- |
| Skip an empty dispatcher branch before emitting | Same contribution for every typed row | Accepted in 1,139 ms |
| Skip urgent jobs | One urgent delivery goes from one job to an empty array | Refused in 1,033 ms |
| Replace the emitted branch with `replaced` | One-row replay returns a different job | Refused in 1,067 ms |
| Replace the emitted repository | Selector postcondition fails on a replayed input | Refused in 936 ms |
| Raise output capacity to 33 | Resource policy violation | Refused in 789 ms |
| Add a priority flag read through a helper | Additional host authority | Refused in 802 ms |

The full native-sequence query could not find a model for the urgent drop
because of incomplete quantifier handling. A search with singleton native
sequence fields found a typed delivery with the urgent label and replayed
both outcomes. A failed subset search still requires the full comparison
query. The imported-selector regression also changes a library body behind
an updated pin and checks a one-row root counterexample.

A separate backend edit reverses the collected array before returning it.
The independent vector expecting release then main receives main then
release. Both outputs have two jobs. Artifact comparison rejects those
exact generated bytes. The unmodified webhook artifact matched 27 probes,
including 7 supplied vectors. It returned successfully on 25 probes,
23 with nonempty input, and recorded 61 selector dispatches and 8 emitted
values. An always-skip regression records nonzero dispatches with zero
emissions. A mutation that bypasses the selector fails the measured
dispatch count even when its empty arrays agree with the reference.

## Measurements

The implementation measured here is commit
`0264389a9e91119696e2986c9407512408a7f544`, based on 0.8 candidate
`188025f41a4ca57256a328129168c5a41bee1ef5`. This run used Node 22.23.1,
npm 10.9.8, Python 3.12.14, Z3 4.13.4 and TypeScript 5.9.3.

| Webhook | 32 | 12,769 | 445 | 481 | 2 | 156.426 | 128.389 |

Verify measures the CLI and all module obligations. Build includes proof,
emission and artifact validation. Z3 discharges the safety and nonempty
admission queries for one selector row. For the lightweight case,
enumeration agrees on all four row and flag assignments at each capacity.
At capacity 9 the outer sequence type crosses from a datatype to a native
sequence. The row proof uses neither outer sequence as an input. It takes
two queries at every capacity. The webhook build uses four additional
queries for the dispatcher and its branch helper. Its selector costs 394
work units, and the batch including visits and output copies stays under
16,384. An additional urgency check at the selector duplicated a 128-label
scan and exceeded that work budget. The dispatcher retains the exact
urgency proof.

Runtime measurements are medians of five warm trials. Both implementations
receive the same cycles of empty, one-row and mixed inputs. The lightweight
cycle has two maximum-length cases with different grants. The webhook cycle
includes a maximum batch in which each delivery has 128 labels. The runs
use 10,000 calls per lightweight trial and 2,000 per webhook trial. Both
paths include boundary decoding and return fresh values. Generated calls
also evaluate the checked source contracts. These measurements establish
local observations and set no CI threshold.

All collector proofs and the measured equivalent comparison finished.
Whole-array source contracts and smaller output capacities supported by
tighter cardinality proofs remain outside this release. In the existing
components pilot, the explicit large-label fold was still unverified at
capacity 16 because of incomplete sequence theory and at 128 because Z3
canceled the query. The native membership versions proved at both sizes.

## Reproduce

Use a fresh checkout with Node 22 and the pinned Python environment. All
build and pilot destinations must be fresh.

```sh
npm ci
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-symbolic.txt
npm test
npm run test:symbolic
npm run demo
npm run pilot -- build/0.9.0/rc/pilot
npm run pilot:support -- build/0.9.0/rc/support
npm run pilot:batch -- build/0.9.0/rc/batch
npm run pilot:components -- build/0.9.0/rc/components
npm run pilot:collect -- build/0.9.0/rc/collect
npm run release:check -- build/0.9.0/rc/distribution
```

The local run used `npm ci --offline --no-audit --no-fund` with a populated
cache and the activated pinned solver environment. The core suite passed
132 tests and the symbolic suite passed 47. The tiny collector oracle
checks all 242 combinations of input sequences of length 0 through 4 and
flag assignments. The webhook pilot checks 14 application and boundary
cases through the generated API and independent TypeScript. The existing
batch pilot matched 261,120 emitted outcomes. The release check installs
the tarball offline into a fresh host and compiles and executes a strict
TypeScript caller against the bundle emitted by the installed compiler.

The collector pilot writes its measurement record, accepted review,
counterexamples and generated bundles in the chosen destination. Function
reports use schema 8 and diff reports use schema 9. Release validation is
local. Hosted CI and remote publication require separate execution.
